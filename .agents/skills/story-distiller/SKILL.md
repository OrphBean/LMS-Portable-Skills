# story-distiller

## What this does

Turns a long story into a set of small, self-contained **scene cards** plus a **language &
visual bank**, written into the portable knowledge-base corpus tree so the `knowledge-base`
plugin can embed and inject them into prompts. The raw prose is too wandering to be a useful
RAG corpus; the *distillation* is what gets indexed.

Documentation for the tool: `story-distiller\README.md`. Source of truth is
`story-distiller\src\`; `dist/` is generated by `tsc`.

## The core technique

The story is segmented into contiguous **slices** (paragraph-aware, with overlap). Per slice,
one LM Studio call is made:

```text
[carried state (slate)] + [story slice]  ->  { scene card, updated slate }
```

The **slate** keeps continuity across the window edge: characters + state/goal, timeline
position, planted items and open threads. It is re-compressed when it grows past `--slate-chars`.
This is the mechanism that keeps abstraction coherent across chunks (RAPTOR-style recursion +
Anthropic contextual retrieval: put *specific* situating context at the top of each chunk, not a
generic "this chunk is a story").

## Usage

```powershell
cd story-distiller

# preview segmentation + prompts only (needs no LM Studio, writes nothing)
node dist/main.js samples/the-queen-of-clouds.md --dry-run

# full distillation into the KB corpus (LM Studio running, model loaded)
node dist/main.js story.md --model "<model-id>" --base-url ws://127.0.0.1:<port> --acts
```

Key flags: `--model`, `--base-url`, `--corpus`, `--slice-chars`, `--overlap-chars`,
`--slate-chars`, `--temperature`, `--max-tokens`, `--max-calls`, `--acts`, `--no-write`,
`--dry-run`. See `node dist/main.js --help`.

## Output (into the KB corpus)

```text
<PortableRoot>\Data\dot-lmstudio\knowledge-base\<corpus>\
  _corpus.md       <- description (KB uses the first paragraph)
  story.md         <- act-by-act logline
  characters.md    <- character sheet (arc across scenes)
  language.md      <- gathered visual/movie language bank
  scene-0000.md …  <- one RAG unit per scene (the retrieval target)
  act-01.md …      <- optional act/sequence summaries (--acts)
  _distill.json    <- raw pass data (derived, regenerable; never hand-edit)
```

To use it: in a chat, set the plugin's `assignedCorpora` to `<corpus>` and leave `Auto-Retrieve`
on. Re-index via `reindex_kb` after a fresh run.

## Requirements & location

- LM Studio running with the server reachable (`ws://127.0.0.1:<port>`; the port is in
  `Data\dot-lmstudio\.internal\http-server.json`).
- A chat model loaded. The distiller can load one by identifier, but the model must be
  available to this install. Only the bundled embedding model is local; the LLMs this mirror
  knows about live on the other (manual-only) install.
- All testing happens on THIS mirror (`E:\lmstudio_mirror`). Never point this tool or an agent
  at the other install.

## Failure handling

Schema failures preserve the raw output to `story-distiller\.failures\slice-<n>.json` and keep
the previous slate so a bad parse never corrupts continuity. Rebuild (`npm run build`) after
editing `src/`; `dist/` is generated, not source.
